### 0.2 評估方式

**探索期用 test 當 validation**（2026-10-05 使用者決定）。val 不再用來選方向。

validation 看兩個主指標，另外兩個照評、當參考（2026-10-05 使用者決定）：

| 角色 | 協定 |
|---|---|
| 主指標 | pose c64、depth 多張 |
| 參考 | pose c5、depth 單張 |

- pose c5 是和已發表方法相同的設定，對外比較時仍以它為準（§0.1）。
- depth 單張同理，是對外比較 depth 的設定。

**什麼時候跑哪個**（2026-10-05 使用者決定）：

- **訓練中**：trainer 每個 epoch 評主指標（test 的 pose c64、depth 多張）。
- **訓練後**：只另外跑參考指標（pose c5、depth 單張）。
- `scared_depth_base.yaml` 用 `pose_eval.dataset: scared_primary`（2026-10-05，md5 `255412fe…`，76 / 79 要同步），結果在 `logs/<exp>/pose_eval/epoch_N/{pose_c64,depth_multi}/`，`best_ate.pt` 依 test 的 c64 挑。和 CLI 差 ≤ 0.1%（GPU 計算設定不同，可忽略）。

四個協定，指令固定（`<ck>` = `logs/<exp>/ckpts/last.pt` 或 `best_ate.pt`；舊 run 沒有 `last.pt`，用 `epoch_10.pt` 代替）。
結果寫到 `outputs/eval/<exp>/<協定>_<last|best>/results.json`，協定名在每行指令的註解裡；其他 ckpt 或非標準參數要自己帶 `--out_dir`。

```bash
# pose c64（主指標）→ pose_c64_*
python pipeline/benchmark/eval_scared.py --ckpts <ck> --split test/pose --n_frames 0 --chunk_size 64 --overlap 16 --no_depth
# pose c5（參考）→ pose_*
python pipeline/benchmark/eval_scared.py --ckpts <ck> --split test/pose --n_frames 0 --chunk_size 5 --overlap 4 --no_depth
# depth 單張（參考）→ depth_*
python pipeline/benchmark/eval_scared.py --ckpts <ck> --split test/depth --n_frames 0 --single_view --depth_protocol afsfm
# depth 多張（主指標）→ depth_multi_*
python pipeline/benchmark/eval_scared.py --ckpts <ck> --split test/depth --n_frames 0 --chunk_size 64 --overlap 16 --depth_protocol afsfm
```

- 用 json 裡的 `n_chunks` 確認協定：c64 是 18 / 9，c5 是 830 / 407。
- 用 `failed_seqs` 確認沒有序列失敗；有失敗時平均值會是 NaN，不要自己重算後當正常結果用。

## 1. 共通問題

這些問題同時影響三個分支，處理一次，三邊受益。

1. **長度外插**：所有時間編碼都吃 clip 內位置 `arange(S)`，訓練 clip 只有 4–12 幀，c64 卻是 64 幀。
   - 受影響的：temporal block 的 1D RoPE、時間相位 RoPE、相對距離 band。
   - 已有的證據：band 在推論時改用絕對距離，c64 −6.8%（T1）；`tfs` 在 c64 推論時壓縮時間位置，0.0609 → 0.0637，反而變差。
   - 已實作、未驗證：`temporal_frame_pos`（temporal 改吃真實幀間隔）配等距抽幀（`tfs_stride`、`tfs_stride_fpos`）。
   - 主指標改成 c64 之後，這一條的優先度變高。
2. **depth 的梯度主導共用參數**：
   - band 的參數收到的梯度，depth 是 camera 的 20–67 倍，方向正交（T2）。
   - 光照 loss 的梯度是 camera 的 20 倍（分支 B）。
   - 任何新成分只要和 depth 共用參數，都可能被 depth 帶著走。
3. **test 的統計力**：pose 只有 2 條序列，c5 的窗口彼此高度相關。test 逐窗 bootstrap（P1）還沒做。
4. **抽樣的錨點保護可能失效**：舊抽樣排序後，第 0 幀通常不是錨點，camera loss 可能被空深度幀吃掉，影響多大還沒量（見 `待處理.md`）。
5. **多機同步**：config 目錄被 gitignore；程式要 commit + push 才能到其他機器；兩台的 `scared_depth_base.yaml` 必須一致。

### 2.2 目標

- **問題**：global block 有冗餘。FastVGGT 指出 global attention 裡很多 token 的 attention 很相似，合併掉也不太影響結果；每個 block 都看全部幀的全部位置，其中很多是重複的工作。
- **目標**分兩步：
  1. **準**：直接告訴各 block / head 該看哪些幀，不讓它自己猜。
  2. **省**：既然知道該看哪裡，不該看的部分就不算，省下計算時間與 memory。
- **現在的做法**：在 global block 8–23，依兩幀之間的距離，對 camera / register token 的 attention 加一個 bias（§2.3 各版本）。只做到第 1 步：bias 加在完整的 attention 上，每一對幀照算，時間與 memory 沒有省；要省得改成硬遮罩（sparse attention / block mask）。
- 第 1 步在 `tfs` 上還沒加分（§2.6），第 2 步等第 1 步至少不傷害 pose 再做。

### 3.2 目標

- **主目標：移除亮度對模型的影響**。亮度變化不該影響 pose 與 depth。文獻上多數方法是因為像素重投影一致性 loss 會被亮度干擾，才設計忽略亮度的模組；`tfs` 目前沒有像素重投影 loss，所以這個干擾在 `tfs` 上不一定存在。
  - 成功條件：改變亮度時 pose 不變。
- **只記錄、不主攻：利用亮度**。內視鏡有很明確的近場光源特性（光源跟著鏡頭走），畫面和亮度高度相關，模型或許能拿亮度當線索；目前沒有好的引導方式。
  - 成功條件：拿掉光照資訊時 pose 變差。
- **現在的做法**：每幀加一個光照 token，經 IlluminationHead 輸出 16×16 的 log 光照圖，目標是影像本身的多尺度 Retinex（MSR）。光照 token 不進入 pose 的計算路徑；2026-09-30 起暫停，等新設計。

### 4.2 目標

- **問題**：global attention 沒有任何時間順序資訊，只有 temporal block 自己有 1D RoPE；而且所有時間編碼都吃 clip 內位置 `arange(S)`，訓練只見過 4–12 幀，c64 的 64 幀超出範圍（§1 第 1 條）。
- **現在的做法**：兩條路。一是把時間編進 global attention 的 RoPE（`ropet`：在原本 2D RoPE 的角度上疊加學出來的時間相位）；二是讓 temporal block 吃真實幀間隔，配等距抽幀把訓練範圍拉到 0–99（`temporal_frame_pos`，`tfs_stride` / `tfs_stride_fpos` 進行中）。

使用規則：

- **佇列**：每個階段開始前先等 GPU 顯存低於 3 GB；失敗就寫入 `logs/.queue_failed` 並停止；`logs/<exp>` 已存在時拒絕覆蓋。用 `setsid` 脫離 session。
- **開跑前先確認磁碟空間**：一支 10 epoch 的訓練會留下 5 個 ckpt（`best_ate`、`best_loss`、`epoch_5`、`epoch_10`、`last`），`tfs` 系列約 44 GB，其他約 38 GB；smoke 約 15–18 GB。
  - 訓練寫到 `logs/<exp>/`，在系統碟（75 是 `/`，916 GB）。佇列裡每支訓練開始前，要檢查系統碟剩餘空間 ≥ 這支的大小 + 10 GB，不足就寫入 `logs/.queue_failed` 並停止，不要等寫到一半才失敗。
  - 一次排多支時，要用「所有排隊的 run 加總」來算，不是只算下一支。
  - smoke 通過後就刪掉它的 ckpt。
  - 完成的 run 可以整個搬到資料碟 `/media/cvml-75/ssd2t/vggt_logs/<exp>`，在 `logs/` 留 symlink（舊 run 都是這樣放的）；ckpt 的 symlink 一律用絕對路徑。
- **程式**：其他機器只用已 push 的 commit。開跑前在進度紀錄寫明用的 commit。
- **config**：其他機器用「繼承 `scared_depth_base` 的單層 delta」，並確認 `scared_depth_base.yaml` 的 md5 和 75 一致。
- **結果回收**：其他機器跑完後，把 `logs/<exp>/` 的 `log.txt`、`dual_stream.jsonl` 等小檔，以及 `outputs/eval/<exp>/` 的 json 拿回 75；ckpt 視需要再拿。
- **兩個 session 同時用 75 時**：開跑前先看 `nvidia-smi` 和 `pgrep -af launch.py`，並在進度紀錄寫一行，避免互相佔用。
