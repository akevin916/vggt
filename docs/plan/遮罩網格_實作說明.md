## 1. 實驗網格

每一格是「一個 ckpt + 一種遮法」，各跑 3 個協定（pose c64、pose c5、depth 多張）。

| # | ckpt | global 遮法（block 8–23） | temporal 遮罩 | 說明 |
|---|---|---|---|---|
| 1 | VGGT-1B | off | — | 對照 |
| 2 | VGGT-1B | M1 | — | |
| 3 | VGGT-1B | M2 | — | |
| 4 | VGGT-1B | M3 | — | |
| 5 | tfs | off | off | 對照，必須重現 c64 0.0609 / c5 0.0709 / depth 0.0413 |
| 6 | tfs | M1 | off | |
| 7 | tfs | M2 | off | |
| 8 | tfs | M3 | off | |
| 9 | tfs | off | on | 只遮 temporal，看 temporal 這條路單獨的影響 |
| 10 | tfs | M1 | on | |
| 11 | tfs | M2 | on | |
| 12 | tfs | M3 | on | |

共 12 組 × 3 協定 = 36 次 eval。VGGT-1B 沒有 temporal block，所以只有 4 組。

遮法定義（「標 1 的 patch」= 違反極線的 patch，見 §2）：

- **M1 camera-only**：camera / register token 不看標 1 的 patch；patch 之間照常互看。等同 PAGE-4D 和現有 gate 的做法。
- **M2 all-query**：所有 token 都不看標 1 的 patch（包括它自己那一幀的其他 patch）。
- **M3 cross-frame**：所有 token 都不看**其他幀**裡標 1 的 patch；同一幀內照看。
- **temporal 遮罩**：`tfs` 的 temporal block 裡，每個 patch 位置沿時間軸 attention 時，不看其他幀在同一位置且標 1 的 patch（自己那一幀照看）。

「不看」的實作：M1、M3、temporal 是在 attention score 上加 −30（和現有 oracle 的 k = 30 一致），不用 −inf，避免整列被遮光時出現 NaN。
M2 例外（2026-10-13 決定）：直接把標 1 的 patch 從 key / value 拿掉，等同 −inf；special token 永遠留著，所以不會整列被遮光。原因見 §3.2。

## 2. 標籤：哪些 patch 標 1

一次性 script，放 scratchpad（約 80 行），在 75 上跑一次，產出兩個 split 的遮罩檔。

### 2.1 步驟

1. **讀幀**：用 `eval_scared.load_sequence(seq_dir, n_frames=0)` 拿全部幀路徑與 GT extrinsics（world→cam 3×4）。
   影像用 `load_and_preprocess_images(mode="crop")` 讀，得到 518×420（SCARED 原圖 1280×1024）。
2. **內參縮放**：`intrinsics.txt` 是原圖的 `fx fy cx cy`，乘上 crop 的縮放比 518/1280（寬）與 420/1024（高）。
   實作時用 `compute_preprocess_meta` 的實際數值，不要寫死。
3. **配對**：每幀 i 往前、往後各找一個鄰居 i±k。k 從 1 開始加，直到 GT 平移 ≥ 該序列相鄰幀平移中位數的 3 倍（避開幾乎只有旋轉、極線退化的配對）。
   找不到的那一側就略過。
4. **GT 相對 pose → F**：
   - R = R₂R₁ᵀ，t = t₂ − R·t₁（world→cam 的慣例）
   - E = [t]×R，F = K⁻ᵀ E K⁻¹
5. **RAFT 對應點**：`flow_mask.raft_flow(img_i, img_j)`（proc 256，fp32），x₂ = x₁ + flow。
   可見性：`coverage_map(反向 flow) > 0.95`，和 `pair_flows` 同一套。
6. **逐像素殘差**：δ = |x₂ᵀ F x₁| / √(a² + b²)，(a, b, c) = F x₁，單位 px。只算可見像素。
7. **兩個鄰居取最大**：δ_i = max(δ_前, δ_後)。
8. **pool 到 patch 格**：518×420 → 37×30 = 1110 個 patch，每格取可見像素的 δ 平均。可見像素 < 30% 的 patch 記為 0（不標）。
9. **門檻**：τ = 全部 patch δ 的中位數 + 3×MAD（每個 split 各算一個 τ）。δ_patch > τ 標 1。

### 2.2 sanity check（不過就停，不產遮罩）

- 全部 patch δ 的中位數必須 < 2 px。超過代表 pose 慣例、內參縮放或配對方向寫錯。

### 2.3 輸出

路徑走 `output_dir_for_exp("scared_epipolar", "motion_mask")`，即 `outputs/_archive/legacy_2026-10-20/motion_mask/scared_epipolar/`：

```
<split>/<seq>.npz      fids [S] int、mask [S,30,37] bool、delta [S,30,37] float32、visible [S,30,37] float32
<split>/stats.json     τ、δ 中位數、每序列與整體的標 1 比例、test/depth 的配對間隔分佈
```

`<split>` 是 `test_pose` 與 `test_depth`。

### 2.4 限制

- **test/depth 是稀疏幀**（相鄰兩張間隔 1–296 幀），配對常常相隔幾十幀以上，RAFT 在這種距離不可靠，δ 會偏大、遮罩會偏多。
  `stats.json` 記下每個配對的幀間隔，depth 的結果要配著這個看。
- 標籤用 GT pose，是 oracle，只回答「上限」，不代表模型能自己學到。
- 違反極線的來源分不開：組織變形、器械、反光、RAFT 本身算錯都會被標 1。

## 3. `aggregator.py` 要改的地方

原則：所有新行為都在「有給遮罩」時才進入；沒給時走原本的程式路徑，輸出 byte-identical。

### 3.1 介面

eval 端在 forward 前設定 aggregator 的屬性（不改 `infer_sequence` 的簽名，也不進 ckpt）：

```python
agg.mask_flags     = None   # [B, S, P_patch] bool；None = 完全不走新路徑
agg.mask_mode      = None   # "camera" | "all" | "cross" | None（只遮 temporal 時為 None）
agg.mask_start     = 8      # global / temporal 從第幾個 aa-block 開始遮
agg.mask_temporal  = False
```

這四個屬性在 `__init__` 給預設值（None / 8 / False），不是 `nn.Parameter`，所以 ckpt 照樣載得進來。

若 `gate_predictor` 存在（帶 gate 的 ckpt），設定遮罩時直接 raise，避免兩種 bias 疊在一起。這次的兩個 ckpt 都沒有 gate。

### 3.2 global block 的分派

在 `_process_global_attention` 的分派裡，`elif gate_logits is not None` 之前加一支：

```python
elif self.mask_flags is not None and self.mask_mode is not None and global_idx >= self.mask_start:
    tokens = self._masked_global_block_forward(blk, tokens, pos, self.mask_flags, B, S, psi, self.mask_mode)
```

- **M1（camera）**：直接重用 `_gated_global_block_forward`，送入 logits = where(flag, +30, −30)。
  現有 bias 公式 min(0, log2 − softplus(g)) 在 g = +30 時約 −29.3、g = −30 時恰為 0，等於只遮標 1 的 patch。
- **M2（all）**：不加 bias。q、k、v 算完並套完 rope 之後，只保留沒被標 1 的 key 和 value（query 不動），再呼叫不帶 `attn_mask` 的 `F.scaled_dot_product_attention`。
  - 為什麼不傳 [B, 1, 1, N] 的 `attn_mask`：flash kernel 不收 bias，一給 mask 就會換 kernel 並把 N×N 攤進記憶體。
    N = S × 1115，c64 時約 71k，N×N 一個 head 約 10 GB。
  - 只支援 B = 1（每條序列被拿掉的 patch 數不同，疊不成 batch），forward 裡 assert。eval 本來就是 B = 1。
  - 代價：M2 是完全看不到，M1、M3 是 −30（權重約 1e-13）；M2 走 flash、M3 走 flex，兩者相減時會混進 kernel 的數值差，靠 §3.4 的全 0 檢查確認夠小。
- **M3（cross）**：bias 同時跟 query 幀與 key 幀有關（[N, N]，c64 時太大不能實體化），走現有的 `_flex_attention`：

  ```python
  def _score_mod(score, b, h, q_idx, kv_idx):
      cross = (q_idx // P) != (kv_idx // P)
      return score + torch.where(cross & flag_tok[b, kv_idx], -30.0, 0.0)
  ```

  `flag_tok` [B, N] 是把 patch 旗標展開到 token 序列（special token 位置填 False）。
  q、k 先轉成 v 的 dtype，與 `_dual_global_block_forward` 相同。

三者的 q/k/v、q_norm/k_norm、rope、proj、ls1、mlp、ls2 都照 `_gated_global_block_forward` 的寫法。只在 eval 用，不需要反傳。

### 3.3 temporal block

在 `_process_temporal_attention` 裡，`self.mask_temporal` 為真、且 block_iter ≥ `mask_start` 時，改走一個展開的 forward（寫法照 `_shared_temporal_block_forward`，但用 block 自己的 ls1/ls2 和 `temporal_rope`）：

- tokens 已經是 (B·P, S, C)：每一列是一個空間位置沿時間的序列。
- bias 形狀 [B·P, 1, S, S]：key 幀 s′ 在該位置標 1 且 s′ ≠ s 時為 −30。special token 那幾列全 0。
- c64 時大小 1115 × 64 × 64 ≈ 460 萬個數，可以直接當 `attn_mask`。

需要把 `block_iter` 傳進 `_process_temporal_attention`（目前只傳 temporal_idx）。

**已對照程式確認（2026-10-13）**：`tfs` 的 `aa_order` 是 frame → temporal → global，`temporal_every` = 3，共 8 個 temporal block，
在 block_iter = 2, 5, 8, …, 23 那一輪、global 之前執行；mask_start = 8 會遮到其中 6 個（8、11、14、17、20、23），前 2 個不遮。

### 3.4 自我檢查（實作完、跑網格前）

- 遮罩全 0 時，M1 的輸出和 off 應完全相同（bias 恰為 0 且走的是既有的 gated 路徑；若有差異只能來自拆兩次 SDPA 的數值誤差）。
- M3、temporal 在遮罩全 0 時換了 kernel，允許極小數值差：c64 相對差 ≤ 0.5%。
- M2 在遮罩全 0 時沒有拿掉任何 key，kernel 和 off 相同，差異只來自展開的 forward；門檻同樣是 c64 相對差 ≤ 0.5%。
- `mask_flags = None` 時，和改動前的 commit 比，同一序列的 extrinsic 要逐位元相同。

## 4. `eval_scared.py` 要改的地方

新增 CLI 參數（不改既有參數名）：

```
--mask_mode {camera,all,cross}   global 遮法；不給 = 不遮 global
--mask_temporal                  同時遮 temporal block
--mask_start 8                   從第幾個 aa-block 開始
--mask_dir <path>                §2.3 的輸出目錄（含 split 子目錄）
```

- 每條序列讀 `<mask_dir>/<split>/<seq>.npz`，依 `load_sequence` 選出的 fids 取列，攤平成 [1, S, 1110]。fids 對不上就 raise。
- 有切 chunk 時取 `mask[:, sub]`，和現在切 override 的位置相同。
- `--single_view` 時不遮（只有一幀，沒有跨幀可遮），印一行警告。
- 輸出的 protocol tag 加上 `_mask{mode}{T}_s{start}`，例如 `_maskcrossT_s8`，與 off 的 json 不會互相覆蓋。
- 每次 eval 在 json 裡多記一欄：實際被遮的 patch 比例。

## 5. 執行順序（在 75 上）

```bash
# 0. 標籤（含 sanity check：δ 中位數 < 2 px，不過就停）
python <scratchpad>/epipolar_mask.py --split test/pose  --out outputs/_archive/legacy_2026-10-20/motion_mask/scared_epipolar
python <scratchpad>/epipolar_mask.py --split test/depth --out outputs/_archive/legacy_2026-10-20/motion_mask/scared_epipolar

# 1. sanity：tfs off 必須重現 0.0609 / 0.0709 / 0.0413；遮罩全 0 的 M1/M2/M3/T 差 ≤ 0.5%
# 2. 網格：每個 (ckpt, 遮法) 跑三個協定
MASK="--mask_dir outputs/_archive/legacy_2026-10-20/motion_mask/scared_epipolar --mask_start 8"
for PAIR in VGGT-1B:checkpoints/VGGT-1B.pt tfs:logs/scared_cam_depth_tfs/ckpts/epoch_10.pt; do
  NAME=${PAIR%%:*}; CK=${PAIR#*:}
  for MODE in off camera all cross; do
    for T in "" T; do
      [[ $NAME == VGGT-1B && -n $T ]] && continue          # VGGT-1B 沒有 temporal block
      EXTRA=""
      [[ $MODE != off ]] && EXTRA="--mask_mode $MODE"
      [[ -n $T ]] && EXTRA="$EXTRA --mask_temporal"
      [[ -n $EXTRA ]] && EXTRA="$EXTRA $MASK"
      O=outputs/_archive/legacy_2026-10-20/mask_grid/${NAME}_${MODE}${T:+_T}          # 每一格、每個協定各自一個目錄
      python pipeline/benchmark/eval_scared.py --ckpts $CK --split test/pose  --n_frames 0 --chunk_size 64 --overlap 16 --no_depth $EXTRA --out_dir $O/pose_c64
      python pipeline/benchmark/eval_scared.py --ckpts $CK --split test/pose  --n_frames 0 --chunk_size 5  --overlap 4  --no_depth $EXTRA --out_dir $O/pose_c5
      python pipeline/benchmark/eval_scared.py --ckpts $CK --split test/depth --n_frames 0 --chunk_size 64 --overlap 16 --depth_protocol afsfm $EXTRA --out_dir $O/depth_multi
    done
  done
done
```

每一格都帶 `--out_dir`，原因有兩個：`checkpoints/VGGT-1B.pt` 不在 `logs/<exp>/ckpts/` 底下，不帶會被 `ckpt_role` 擋下；
`tfs` 的 off 若走預設路徑，會覆蓋 `outputs/_archive/legacy_2026-10-20/eval/scared_cam_depth_tfs/` 裡現有的正式結果。

批次的第一步是 sanity，任何一項不過就停止並回報，不跑網格。

## 6. 判讀（事前定，跑之前不再改）

以同一 ckpt 的 off 為基準，算相對變化。

- **pose**：c64 與 c5 都 ≤ −4%，且兩條序列（ds3、ds5）同方向 → 這種遮法值得往步驟 1（訓練）走。
  c64 與 c5 都 > −2% → 這種遮法在 SCARED 上沒有頭空。其他 → 回報討論。
- **depth 多張**：≤ −2% 算有改善（計劃書的擺動參考量）。
- **temporal**：比較 #9 vs #5、#10–12 vs #6–8。差異 < 2% 視為 temporal 這條路不是洩漏的主要來源。
- 每一格附上被遮的 patch 比例，只當參考，不參與判讀。
- VGGT-1B 的結果只回答「沒訓練過的模型對遮罩的反應」；它的誤差主要來自域差，結論不直接轉移到 `tfs`。
