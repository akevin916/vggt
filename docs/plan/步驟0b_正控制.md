## 1. 干擾物怎麼做（2026-10-13 修訂：兩種都做、分階段，Kevin 選 A）

**內容**：從 **train split 另一條序列**裁一塊 156×126 px 的組織影像（518×420 的約 9%，約 11×9 = 99 個 patch）。
- 用別條序列，避免貼片內容和本序列真實的組織重複、被模型當成正確對應。
- 選紋理多的區塊（例如血管清楚、沒有反光的位置），VGGT 才會拿它去配對；純色塊可能被直接忽略，干擾太弱。
- 邊緣直接貼上（不羽化），隨機種子固定，裁哪一塊、貼在哪裡都寫進輸出的 json。

**兩種運動**：
- **不動（D-static）**：貼在畫面固定位置（右下象限），所有幀相同。相機在動、它不動，模擬跟著鏡頭的器械或鏡頭髒污。
  風險：SCARED 每幀相機位移很小，固定貼片和場景的相對位移可能只有幾 px，違反極線的程度可能不夠。
- **移動（D-move）**：從左上開始，每幀**斜向**移動 3 px（x、y 各 2.12 px），碰到邊界反彈，模擬器械在畫面中移動。
  （2026-10-13 修訂，原本是水平 3 px。）順著極線方向的移動不算違反極線，所以方向有差。用 GT pose 試算、假設 RAFT 完美追到貼片，
  超過步驟 0 門檻 τ = 3.52 px 的比例（recall 上限）：不動 0.23 / 0.16（ds3 / ds5）、水平 0.83 / 0.79、垂直 0.88 / 0.88、斜向 0.89 / 0.92。
- px 都是 518×420 座標下的值；換回原圖 1280×1024 是 385×307 的貼片、每幀 7.4 px。

**做法**：一次性 script 為每種運動各寫一份 test/pose 副本：`image_left` 貼上干擾物，`cam_data` 用 symlink 指回原始資料；同時存 GT 遮罩（貼片蓋到 ≥ 50% 的 patch 標 1，格式同步驟 0 的標籤 `[S,30,37]`）。
eval 時把 `--scared_root` 指向副本，其餘參數不變；不需要改 repo 程式。

**分階段**：
1. 第一階段（兩種都跑）：#a 原始不遮、#b「貼了不遮」、在副本上重算極線標籤並量 recall。約 3 次 c64（#a 共用）+ 2 次 RAFT 標籤。
2. 第二階段：#c 只對 D 較大的那一種跑。兩種 D 都 < 5% → 干擾物放大到約 20% 面積，重做第一階段一次。
   **#d 與判讀第 3 條固定在 D-move 上做**（2026-10-13 修訂）：不動的貼片本來就幾乎不違反極線（recall 上限 0.16–0.23），
   在它上面判「標籤能不能用」會因為設計而不過。D-move 的 D < 5% 時 #d 的 R 沒有意義，只報 recall，第 3 條回報討論。
3. #e、#f（原始 SCARED 上的隨機遮罩對照）要用「c 裡最好的組合」，排在第二階段之後。

**c5**：正控制只跑 c64。最後選出的最好組合補一次 c5；若該組合是 M2 或 M3，先跑一次「遮罩全 0」的 c5 檢查（差距須 ≤ 0.5%），因為步驟 0 只在 c64 做過全 0 檢查，而 M3 在 c5 +28% 尚未排除是實作問題。

**test/depth**：正控制只量 pose，不處理 test/depth 標籤，標為未解決。

## 2. 要跑的組合（只用 `tfs`，協定 pose c64）

| # | 影像 | 遮罩 | 遮法 × 起始層 | 回答 |
|---|---|---|---|---|
| a | 原始 | 無 | — | 基準（應為 0.0609） |
| b | 貼干擾物 | 無 | — | 干擾物讓 pose 變差多少（D） |
| c | 貼干擾物 | GT 遮罩 | {M1, M2, M3, M3+T} × {0, 8, 16} | Q3、Q4：哪個組合救回最多 |
| d | 貼干擾物 | 極線標籤（在副本上重算） | c 裡最好的組合 | Q2：標籤能不能取代 GT |
| e | 原始 | 隨機遮罩（與極線標籤同比例，3 個 seed） | c 裡最好的組合 | Q2：極線標籤在 SCARED 上是否比隨機好 |
| f | 原始 | 極線標籤 | c 裡最好的組合 | 與 e 對照 |

共約 1 + 1 + 12 + 1 + 3 + 1 = 19 次 c64。最後只對 c 裡最好的組合補跑 c5 確認。

## 3. 指標

- **D（干擾強度）** = (b − a) / a。
- **救回比例 R** = (b − 遮後) / (b − a)。1 = 完全救回，0 = 沒效果。
- **標籤 recall** = GT 遮罩內被極線標籤標到的比例；另報 GT 遮罩外被標的比例。

## 4. 判讀（事前定）

1. **干擾夠不夠強**：D ≥ 5% 才往下判讀。D < 5% → 干擾物放大到約 20% 面積重做一次；仍 < 5% → 回報（代表 `tfs` 本來就會忽略固定不動的內容，正控制設計要換）。
2. **遮罩機制（Q3、Q4）**：c 的最好組合 R ≥ 0.7 → 機制有效，該組合就是遮法與起始層的答案。全部 R < 0.3 → 遮罩這招連已知干擾都擋不住，回頭重想機制。中間 → 回報。
3. **標籤（Q2）**：只在 D-move 上判。recall ≥ 0.8 且 d 的 R ≥ 同一組合用 GT 遮罩時 R 的 0.7 倍 → 標籤可用。否則標籤要改。
4. **SCARED 本身（Q1）**：f 比 e 的平均好不到 1% → 極線標籤在原始 SCARED 上不比隨機好。
5. **合起來（Q5）**：2、3 都通過，但 4 顯示 SCARED 上無差異 → 問題在資料，走步驟 3（換資料集）。

## 5. 成本與程式

- 兩支一次性 script，放 scratchpad：貼干擾物並存 GT 遮罩（約 40 行）、產生隨機遮罩（約 15 行）。
- 極線標籤 script 在副本上重跑一次（RAFT，test/pose 全部幀）。
- 副本約 3 GB 磁碟。eval 19 次 c64 + 1 次 c5，都在 75 上跑。
- 批次第一步是 sanity：#a 必須重現 0.0609，不符就停。

## 6. 限制

- 固定在畫面上的干擾物比真實的組織變形簡單得多，正控制成功只代表「機制能擋明顯的干擾」，不代表能擋內視鏡裡細微的不可靠區域。
- 只用 `tfs`；VGGT-1B 的反應不在這一步回答。
