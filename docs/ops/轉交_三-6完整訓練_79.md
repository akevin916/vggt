## 1. 這個 run 是什麼

- **問題**：global attention 每個 query 只看 25% 的 key，從頭訓練下精度能不能不掉。
- **做法**：`scared_cam_depth_tfs_fpos_seed43`（下稱 `tfs`，規格裡寫 `tfs_abs`）的完整配方，從 `checkpoints/VGGT-1B.pt` 開始，10 epoch × 1500 步、lr 3e-5、seed 43；global block 8–23 從第一步就帶**固定**的幀距遮罩。
- **遮罩**：`outputs/colmask/reluni_rand_s0.npy`，bool `[6, 8, 8]`。依 query 幀與 key 幀的距離 Δ 分 6 桶（Δ=1｜2｜3–4｜5–8｜9–16｜≥17），每桶在 8×8 tile 裡隨機固定 16 格保留（25%），tile 週期鋪滿 30×37 的 patch 格子。永遠保留：同一幀、第 0 幀、special token、query 自己的 key；每個 query 幀另有一個平均 token。沒有學習參數。
- **和 `tfs` 唯一的配方差異**：aspect 固定 518×420（遮罩是 30×37 格），`tfs` 是隨機 aspect 0.33–1.0。

config：`pipeline/training/config/c3_full_reluni_b25.yaml`（parent 鏈到 `scared_depth_base`，全部在 git，commit `fe75dbe`）。

## 3. 執行

```bash
cd /home/yang/Desktop/vggt
torchrun --nproc_per_node=1 pipeline/training/launch.py --config c3_full_reluni_b25 --resume > logs/c3_full_reluni_b25.out 2>&1
```

- 一定要帶 `--resume`。不帶的話 trainer 看到已有 `last.pt` 會拒絕啟動（防止覆蓋）。
- 啟動後 log 應出現：`Mid-epoch resume: epoch 3, fast-forwarding to iter 1001`。沒有這行就停下來，不要從頭跑。
- 每步約 1.9 秒（原機 RTX 5090，功耗上限 400 W），剩約 9500 步 ≈ 5–6 小時，另加每個 epoch 結束時約 10 分鐘的 test eval。
- 每 500 步覆寫一次 `last.pt`。中斷了就用同一條指令接續。

## 6. 判讀（規格事前定，跑之前不改）

## 8. 已知的坑

- **遮罩走 flex_attention**：會比 `tfs` 慢，eval 也慢約 20%。這是預期的，遮罩只把被丟的 key 的分數壓成 −1e4，不省計算。
- **flex 的 shared memory**：幀距遮罩的 kernel 已設成小 tile（`RM_FLEX_OPTS`），原因是預設 tile 在 RTX 5090 上超過 shared memory。如果 79 的 GPU 不同、出現 `No valid triton configs ... out of resource`，就是這個問題。
- **不要動 config**。aspect 固定、`save_steps_freq: 500` 都是刻意的。
- 規格全文、前面各實驗的數字：`docs/topics/d1_colmask.md`（三-2），以及貢獻三的執行說明（三-3／三-4）。
