## 0. 要回答的問題

到目前為止只量了最後的指標（c64、c5、depth），中間的機制沒有量過。核心假設是一條四步的鏈：

1. head 在「看哪幾幀」這件事上有冗餘。
2. 冗餘是因為缺少區分彼此的條件。
3. 加上幀距離的 bias 之後，head 會分工。
4. 分工之後 pose 變準。

本文件的量測對應如下：

| 代號 | 量什麼 | 回答的問題 | 對應假設 |
|---|---|---|---|
| M1 | 學到的參數 s、σ、β | d 有沒有被模型用到 | 鏈的第 3 步、A1 |
| M2 | bias 相對於原本 logit 的大小 | bias 夠不夠大，能不能移動注意力 | 鏈的第 3 步 |
| M3 | 幀距離的注意力曲線 | 注意力有沒有照設計改變；錨點幀佔多少 | 鏈的第 3 步、A1 |
| M4 | head 之間的相似度 | 有沒有冗餘；加 d 後有沒有分工 | 鏈的第 1、3 步 |
| M5 | 距離遮罩掃描 | 模型實際需要哪些幀；「省」可不可行 | 目標的第 2 步、A0 |

## 1. 開始前要確認的三件事

這三件事會改變量測的定義，先看程式確認，寫進 §7 的紀錄。

1. **bias 的方向**：是加在「camera / register token 當 query」的那幾列，還是「camera / register token 當 key」的那幾欄，或兩者都有。下文預設是前者。
2. **第 0 幀（錨點）有沒有特別處理**：bias 對第 0 幀是照距離算，還是另外處理。
3. **attention 的實作**：如果 block 用的是 `scaled_dot_product_attention` 這類不回傳權重的寫法，要另外重算（見 §2.2）。

### 2.1 比較的 ckpt

### 2.2 抽取什麼

- **位置**：global block 8–23，每層每個 head。
- **哪幾列**：只存 camera token 當 query 的列；register token 另外存一份，分開統計。
- **取 softmax 之後的權重**。
- **重算的做法**：只對需要的那幾列算 `q · kᵀ`（RoPE、bias 都要照原本的順序套用），再做 softmax。不要為了拿權重改掉整個 block 的計算路徑。
- **資料**：`test/pose` 的兩條序列（ds3、ds5），分開存。
  - c64：chunk 64、overlap 16，全部 18 / 9 個 chunk。
  - c5：chunk 5、overlap 4，共 830 / 407 個，固定每 8 個取 1 個（從第 0 個開始），不要挑。

### 2.3 基本量的定義

以下 `i` 是發問的幀，`j` 是被看的幀，`S` 是 chunk 的幀數，`l` 是層，`h` 是 head。

- **幀層級的注意力** `A[l,h,i,j]`：第 i 幀的 camera token 分給第 j 幀「所有 token」的權重加總。每一列對 j 加總為 1。
- **三種特別的成分**，分開報告，不混在距離曲線裡：
  - 自己：`A[i,i]`
  - 錨點：`A[i,0]`（i ≠ 0）
  - 錨點幀自己那一列（i = 0）：單獨統計
- **距離曲線** `P[l,h,Δ]`：對所有 `|i−j| = Δ`、且 i ≠ 0、j ≠ 0、j ≠ i 的幀對，取 `A[i,j]` 的平均。
- **一律報「相對均勻值的倍數」**：`A × S`。完全平均分配時每幀是 1，這樣 c5 和 c64 才能放在一起比。
- **c64 的距離分箱**：1、2、3、4、5–8、9–11、12–16、17–32、33–63。11 是 `abs` 的截斷點，要落在箱的邊界上。c5 不分箱（Δ = 1–4）。

## 3. 量測

### M1：學到的參數（不用跑模型）

- **做法**：直接讀 ckpt，取每個 head 的偏好距離 s、帶寬 σ，每層的強度 β（`alt` 系列只有每層的強度）。同時記下初始值。
- **報告**：每層一列，列出 β、s 在 16 個 head 之間的最小 / 中位 / 最大、σ 的中位數。
- **看什麼**：
  - |β| 離初始值多遠。接近 0 表示該層沒在用。
  - s 在 head 之間有沒有散開。都擠在初始值附近表示沒有分工。
  - G3 對 G1：`tfsd_abs` 的 |β| 是否明顯小於 `abs`。

### M2：bias 相對於原本 logit 的大小

兩個數字，都是每層每個 head 一個值，再對資料取平均。

- **比例**：在 camera token 那一列，`bias 在各幀之間的最大值 − 最小值` 除以 `不含 bias 的 logit 在所有 key 之間的標準差`。
- **實際移動量**：同一次 forward 裡，只在該層的 softmax 把 bias 拿掉重算一次（不往後傳），比較有 bias 和沒 bias 的幀層級注意力：
  `TV = 0.5 × Σ_j |A_有 − A_無|`
  範圍 0–1，意思是「有多少比例的注意力被 bias 搬到別的幀」。
- **看什麼**：TV 是主要數字，比例只是輔助說明原因。
- **報表格式**：c64、c5 各一張表，每層一列、每個有 d 的模型一欄，格子寫「TV（比例）」；最後三列是全部平均、register 的 TV、原本 logit 的標準差。圖：每層 TV 的折線，每個模型一條。

### M3：幀距離的注意力曲線

- **做法**：照 §2.3 算 `P[l,h,Δ]`、自己、錨點，每個 ckpt、c5 和 c64 各一份。
- **報告**：
  - 每組（G1–G4）的「有 d − 沒有 d」差異。
  - 錨點佔比、自己佔比，前後各是多少。
- **加權版**（選做）：把每個 key 的權重先乘上它的 value 向量的範數再加總。注意力高但 value 很小的 token 實際貢獻不大，兩版方向不同時以加權版為準。
- **看什麼**：
  - 差異曲線的形狀是否符合學到的 s（M1）。s 小的 head 應該在小 Δ 變多。
  - 錨點佔比在加 d 之後是上升還是下降。下降很多就要注意：pose 是相對第 0 幀定義的。
  - `tfs` 本身（沒有 d）的曲線是否已經偏向鄰近幀。如果是，表示 temporal 已經讓模型學到同樣的偏好。

### M4：head 之間的相似度

- **做法**：每個 head 的特徵向量是 `[P 在各距離箱的值, 錨點佔比, 自己佔比]`，正規化成加總為 1。同一層內兩兩算 Jensen–Shannon 距離，取平均，得到每層一個「多樣性」數字。
- **參考量**：同一個 ckpt 在 ds3 和 ds5 上各算一次，兩者的差當作「沒有意義的波動」有多大。
- **看什麼**：
  - 沒有 d 的模型，多樣性是否偏低（鏈的第 1 步：冗餘是否存在）。
  - 加 d 之後多樣性是否上升，而且上升幅度超過參考量（鏈的第 3 步：有沒有分工）。
- **報表格式**：c64、c5 各一張表，每層一列、每個模型一欄，格子寫「多樣性（ds3/ds5 差）」；最後一列是平均。圖：每層多樣性的折線，誤差棒是 ds3/ds5 差。

### M5：距離遮罩掃描

這一項直接用正式指標量，不看注意力。

- **做法**：推論時在 global block 8–23 加硬遮罩，把 `|i−j| > k` 的幀對遮掉（logit 設為負無限大）。第 0 幀預設保留不遮。
- **掃的值**：k = 1、2、4、8、11、16、32、不遮。
- **兩種範圍**：
  - (a) 只遮 camera / register token 當 query 的列。
  - (b) 所有 query 都遮（patch 也遮）。
- **另外一支**：只遮錨點（j = 0，其他都不遮），量錨點的重要性。
- **模型**：底座、`tfs`、`tfsd_abs`。
- **指標**：pose c64、depth 多張，指令和判讀照計劃書 §0.2。
- **temporal block 不遮**，只動 global block。
- **看什麼**：
  - 指標在 k 多大時回到「不遮」的 2% 以內。這個 k 就是模型實際需要的範圍。
  - `tfsd_abs` 能承受的 k 是否比 `tfs` 小。是的話，表示 d 確實改變了模型依賴哪些幀，即使指標沒有加分。
  - 範圍 (b) 的結果決定「省」可不可行：(b) 在小 k 仍不掉，才值得做稀疏 attention。
  - 多張 depth 在 (b) 掉得比 pose 快多少。
- **報表格式**：pose c64、多張 depth 各一張表，每個設定一列、每個模型一欄，格子寫「數字（相對同一範圍不遮的 %）」。圖：橫軸 k、縱軸相對不遮的 %，範圍 (a)、(b) 各一格，每個模型一條線，±2% 畫虛線。
- **「不遮」的參考值**用同一條程式路徑跑 k = 不遮，不直接用正式數字；正式數字只用來檢查這條路徑沒有偏掉（pose 0.5%、depth 1% 以內）。

### 總表

每個模型一列，把判讀表要用的數字並排：M1 強度中位數、M2 TV（c64、c5）、M3 錨點佔比（c64、c5）、M4 多樣性與參考量（c64）、M5 回到 ±2% 的最小 k（pose (a)、pose (b)、depth (b)）。

## 4. 視覺化

### 4.1 三種圖

| 圖 | 內容 | 規格 |
|---|---|---|
| V1 幀對幀矩陣 | 縱軸發問的幀、橫軸被看的幀，顏色是 `A × S` | 一組三張：沒有 d、有 d、差異。前兩張同一個色階；差異圖用紅藍兩色、0 在中間。自己那一格留白。每層一排，每個 head 一小張 |
| V2 距離曲線 | 橫軸 Δ、縱軸 `P × S` | 每層一格，每個模型一條線。錨點和自己用另外的點標在旁邊，不接進曲線 |
| V3 影像疊圖 | camera token 對某一幀各 patch 的注意力疊在影像上 | 一組三列：沒有 d、有 d、差異。同樣共用色階 |

- c5 和 c64 分開畫。c64 的矩陣只取一個 chunk 當例子，另附全部 chunk 的平均。
- 第 0 幀的值通常遠大於其他幀，色階的上限用「不含第 0 欄」的值來定，第 0 欄另外標數字。

### 4.2 人眼檢查的規則

1. **看圖之前先寫下預期**，寫在 §7。例如「加 d 之後，鄰近幀裡紋理清楚的組織會變亮，高光區會變暗」。
2. **樣本按規則挑**：用成對的兩個模型在每個窗的誤差差距排序，取差距最大的 5 個（有 d 比較好）、最大的 5 個（有 d 比較差）、中間的 5 個。規則定好才出圖。
3. **盲測**：把「沒有 d」和「有 d」隨機排左右、遮住標籤，記錄猜對的比例。15 組裡猜對不到 12 組，就不算看得出差異。
4. **重要區域要變成遮罩**：把想看的區域定義成可以自動算的遮罩（例如高光：三個通道都超過某個亮度；黑邊；其餘組織），對整個 test 算「注意力落在遮罩內的比例」。圖只用來確認這個數字的意思。

### 4.3 一個限制

d 只直接改 camera / register token 的注意力，patch 之間的注意力只會間接受影響。V3 看不出變化不代表 d 沒有作用，要以 V1 和 M2 的 TV 為準。

## 7. 紀錄

結果寫回計劃書 §2.4（新增「專項量測」小節）與 §2.7（一行：日期、量測代號、一句觀察）。這裡只記本文件自己的前置事項。

- §1 的確認結果（2026-10-05，讀 `vggt/models/aggregator.py`）：
  - **bias 的方向**：只加在 camera / register token 當 query 的列。每幀有 5 個特別 token（1 個 camera + 4 個 register）；被看的第 j 幀的所有 token（含它的 camera、register、patch）共用同一個 bias。patch 當 query 的列走另一條沒有 bias 的 SDPA。所有分支 A 的 run 都是 `dual_stream_scope: camera`，`alt` 系列在程式裡固定是 camera。
  - **第 0 幀的處理**：
    - band 系列（band_camera、`abs`、`odo`）：被看的第 0 幀和自己那一幀，bias 固定為 0。其他幀的 bias 一律 ≤ 0（公式是 −β × 平方項，下限 −20）。所以在 logit 不變的前提下，bias 只會把注意力從其他幀搬到錨點和自己，不會讓錨點佔比下降。
    - `alt` 系列：錨點和自己那一幀只保留正的 bias，負的截成 0。也就是只能加強錨點，不能壓低。
    - 發問的是第 0 幀時（i = 0），它看其他幀照常加 bias。
  - **attention 的實作**：全部是 `F.scaled_dot_product_attention`，不回傳權重。沒有 d 的模型走 `vggt/layers/attention.py` 的 `fused_attn`；有 d 的模型走 `_dual_global_block_forward`，camera / register 那幾列另外算一次帶 bias 的 SDPA。兩者都要照 §2.2 重算。
