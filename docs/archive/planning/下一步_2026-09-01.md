## 0. 目標的改變

**舊目標**：動態場景下的前饋式 pose 精度（Sintel ATE / SCARED snippet ATE）。
**新目標**：在維持精度的前提下，**降低推論的計算時間與記憶體使用量**。

不是 real-time、不是部署、沒有 fps 目標 —— 只有兩條要壓下去的曲線。

**這個改變的連帶影響**：

- 「裝不下長序列」從工程限制升級成**方法問題**。VGGT 單次上限 80 幀 → 必須 Sim3 拼接
  → 拼接讓 ATE 擺動 −1%~+32% 不可預測 → 全序列 evo ATE 目前**明講不報**
  （[method.md](../method.md) §9.3、[status.md](../status.md) B.2）。
  **省記憶體同時就是在解這個填不了的表格欄位。**
- 「增量重建」不是必需品。chunk + 拼接已經能跑，incremental 解的是拼接**精度**，不是效率。

## 1. 已量到的事實 —— 成本 profiling

`training/diag/profile_cost.py`｜`outputs/profile_cost/inst_gts/`｜`inst_gts.pt`、RTX 5090、
bf16 autocast、`no_grad`、隨機輸入（成本與內容無關）。

### 1.1 一句話

**時間是 O(S²)、記憶體是 O(S)。兩個瓶頸不是同一個東西。**

### 1.2 記憶體

| | 權重 floor | activation 斜率 | 二次項佔比 | OOM |
|---|---|---|---|---|
| 518px | 4.70 GiB | **0.336 GiB/幀** | S=64 時僅 ~4% | S=80（64 幀 = 28.3 GiB） |
| 994px | 4.72 GiB | **1.99 GiB/幀** | — | S=12（8 幀 = 22.6 GiB） |

activation 記憶體**幾乎純線性**。flash attention 不落地 `(S·P)²` 矩陣，
所以佔位置的是 **token 本身**，不是 attention 矩陣。

80 幀上限就是線性外推撞牆：`4.70 + 0.336×80 ≈ 31.6 GiB`。

### 1.3 時間

518px 擬合 `0.00083·S² + 0.036·S`。S=64 時二次項 3.4 s > 線性項 2.3 s。

模組分解（殘差 1–4%）：

| 模組 | 518px S=32 | 994px S=8 | peak/call |
|---|---|---|---|
| **global** | **1.23 s (57%)** | **1.03 s (52%)** | 2.12 GiB |
| frame | 0.35 s (16%) | 0.38 s (19%) | 1.11 GiB |
| patch_embed | 0.21 s (10%) | 0.26 s (13%) | 1.73 GiB |
| depth_head | 0.18 s (8%) | 0.19 s (9%) | **8.52 GiB @994** |
| temporal | 0.11 s (5%) | 0.11 s (5%) | 1.29 GiB |
| gate | 0.001 s (**0.05%**) | 0.001 s | 0.34 GiB |

> ⚠️ **量測陷阱（已修）**：`enable_gate` 開啟後 global block 8–23 走
> `_gated_global_block_forward`，直接呼叫 block 的**子模組**，block 自己的 `forward` 不會被呼叫
> → `register_forward_hook` 會**靜默漏掉 16/24 個 global block**（把 global 低估成 34%）。
> 正解是攔 `Aggregator._process_*` 方法。`profile_cost.py` 的 `residual_sec` 就是這件事的檢查。

### 1.4 直接推論

| 命題 | 成立？ |
|---|---|
| 「global attention 太肥」 | **時間成立**（57%、唯一二次項來源）；**記憶體不成立**（線性） |
| P（解析度）比 S（幀數）貴 | **成立**。P ×3.68 → 每幀記憶體 ×5.9、時間 ×5.5 |
| gate 的推論成本 ≈ 0 | **成立**（0.05%） |
| 減 token 同時解兩邊 | **成立**。記憶體線性降、時間平方降 |

**共同解是「減 token」；「改 attention 結構」只是時間那一側的額外選項。**

### 1.5 順手撿到的三個低風險改動

1. **權重是 fp32**（autocast 只轉運算不轉權重）→ 轉 bf16 省 ~2.3 GiB ≈ **多 7 幀**。
2. **`depth_head` 在 994px 單次瞬時 8.52 GiB**，全模型最大單一峰值。純 pose 場景關掉它，
   高解析度天花板馬上鬆。（但預測與訓練 depth 本身是必要的 → 只能在 pose-only 的推論路徑關。）
3. **temporal 只佔 5% 時間** → 要重新設計、加強時序建模，**預算很寬鬆**。

## 2. 四個方向的整理

### 2.1 Gate

**現況（已量到）**：機制成立但兌現不足。`predicted −0.15%` vs `oracle −5.85%`，
但同一份 `g` 二值化 / top-20% 就到 −4.26% / −4.76%（走掉 oracle 頭空的 81%）。
見 [status.md](../status.md) A.2。

**三個要處理的問題**：

1. **objective 錯配**。現在 `L_gate = BCE(σ(g), m*_inst)`，訓的是「像不像 GT mask」，
   **不是「壓了它 pose 有沒有變好」**；bias 路徑還 detach，pose 梯度回不到 predictor
   （`gate_pose_grad` flag 存在但沒當主線）。這與 A.2 的現象一致：排序能力沒問題
   （AUC 0.844），**絕對值 calibration 爛**（預測 0.145 的 bin 實際 0.345），
   因為 BCE 從來沒要求它落在 bias 函數的有效區間。
2. **不是 attention 接線壞掉**。前向 bug 已於 2026-07-09（`e064087`）修正。
   現在的病因是 bias 函數死區（**此判讀未確認**）。
3. **內視鏡上完全不點火**。`inst_g` 在 SCARED keyframe3/4 的 σ(g) 平均 0.005–0.010，
   `frac_gt_half = 0.0` —— 一個 patch 都沒越過 kink。原因是**內視鏡沒有「會動的物體」**，
   動態物 gate 沒有訊號可學。

**內視鏡的重新定義**：語義要從 **motion gate** 換成 **reliability gate** ——
該壓的是 specular highlight、非剛體形變（呼吸／蠕動／器械推擠）、煙霧／血／沖水、
器械遮擋、AWB 重鎖與 gain 跳階。[method.md](../method.md) §5.2 已經預留了 "reliability-gate"
這個詞，C2 corruption 就是為它留的。

**與效率的交集**：現在的 gate 是 soft bias，**token 還在，attention 一格都沒省**。
若 A.2 成立（二值化的 pose 還比 soft 好），就有理由把 gate 從「壓權重」改成
**真的丟掉 patch** → 同時是精度修正與減 token 手段。**這是唯一三重回報的路徑。**

### 2.2 Self-supervised

**必要**：私人內視鏡資料集（lesion / gastric）沒有 GT。

**⚠️ 這個 repo 已經在這裡摔過兩次，設計必須繞開**：

- `L_ego_flow`：陰性收束，病因是**低視差序列任何 flow loss 都無效**（[topics/ego_flow.md](../topics/ego_flow.md)）。
- static-photo loss：clean 重跑負結果，最佳 0.1583 比起點 0.1533 還差且單調惡化。

而內視鏡恰恰是低視差場景（GT 相機位移在 gap 240 之後飽和，鏡頭會逗留與折返）。
→ **「photometric warping 當自監督主訊號」有高機率重蹈覆轍，不建議當第一選擇。**

候選替代訊號（皆未驗證）：

- **跨 view 幾何一致性**：同一 3D 點在不同幀的 `world_points` 應一致。VGGT 天生輸出，免費。
- **leave-one-out 一致性**：拿掉某些 patch / frame，pose 不該變 —— 這正好可以當
  **gate 的自監督 objective**，與 2.1 合流。
- **蒸餾**：用 SCARED（有 GT）訓的模型當 teacher 標私人資料集。

**評測問題未解**：沒有 GT 的資料集，自監督訓完要怎麼證明它變好？（重投影誤差？解剖標記？）

### 2.3 Attention

**要拆成兩件不同的事**（依 §1.4）：

- **省記憶體** → 減 token（gate 剪枝／keyframe／解析度／pose-only 關 depth head），
  **與 attention 結構無關**。
- **省時間** → 才是改 global attention（57%、二次項來源）。

**⚠️「temporal 對時序關聯性還很弱」目前無法成立**：`inst_gts` 相對 `inst_g` 的 −12%
（0.1533 → 0.1343）**混著 temporal 結構與 camera_smooth loss 兩個因子**，從 2026-07 掛到現在沒拆。
**不知道 temporal 貢獻是 0 還是全部，就不知道要修什麼** → 拆因子是重新設計 temporal 的前置條件。

好消息：temporal 只佔 5% 時間，加容量的預算很夠（§1.5）。

### 2.4 增量重建

**降回低優先，符合原本的判斷。** 純效率目標下 chunk + 拼接已經能跑；
它真正解的是**拼接精度**（§0），不是效率。

⚠️ **賽道很擠**：CUT3R、StreamVGGT、Spann3R、MASt3R-SLAM、VGGT-Long 都在做
「把 DUSt3R/VGGT 變 streaming」。**純粹的 incremental 化不會是貢獻點** ——
貢獻必須落在「內視鏡專屬的 reliability gate + 自監督」這個組合。
**這點需要先做一次文獻確認再定案。**

## 3. 尚未確認的判讀（不可當既定事實使用）

1. gate 兌現不足的病因是 **bias 函數死區**（calibration 欠自信 → 落在 kink 平段）。
2. 內視鏡的 gate 應改為 **reliability gate**（而非 motion gate）。
3. photometric warping 類自監督在內視鏡上會因低視差而失效。
4. 減 token 是記憶體與速度的共同解，優先於改 attention 結構。
