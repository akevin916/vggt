# 評估管線：平行化執行圖

> 目標順序（由使用者定義）：
> 1. 先復現**跟過去計畫相同的測試**（過去只支援左右眼 pair 的輸入／輸出）
> 2. 說明現在**不只 pair，也能 sequence**，跑在**私人資料集**上
> 3. 比較指標使用 **PSNR**
> 4. 若要說服「我們的方法更好」，再與 SOTA 在**公開資料集**比較：**EndoSfM3D → VGGT → MonST3R**
> 5. **SOTA 放什麼圖，我們就放什麼圖**

---

## 核心判斷：什麼在關鍵路徑上

這批任務的瓶頸資源**不同**，所以不該排成一條序列：

| 任務性質 | 瓶頸資源 | 能否並行 |
|---|---|---|
| 推論 / 訓練 | **GPU（單張 5090，獨佔）** | ❌ 彼此互斥，是關鍵路徑 |
| 公開資料集下載與前處理 | 磁碟 I/O、網路 | ✅ 完全不吃 GPU |
| baseline 環境建置（EndoSfM3D / MonST3R） | CPU、套件相依 | ✅ 完全不吃 GPU |
| 讀 SOTA 論文、盤點圖表規格 | **人的時間** | ✅ 零計算成本 |
| 畫圖 / 出表 | CPU | ✅ **前提是中間結果已落盤** |

**結論：GPU 是唯一的稀缺資源。任何讓 GPU 閒置去等待「人」或「下載」的排法都是錯的。**

---

## ⭐ 最關鍵的一步：先定「輸出契約」

**「看 SOTA 放什麼圖」必須排在所有推論之前。**

它零計算成本，但它決定推論時要落盤什麼。如果等跑完才決定圖長什麼樣，就得為了補一張圖重跑整批 GPU 推論——這是這條線上最貴的浪費。

做法：讀完 EndoSfM3D / VGGT / MonST3R 的論文後，先寫出一份 **dump 規格**，然後讓每一次推論都**一次性落盤足夠的原始陣列**：

- per-frame depth / point map（原始 float，不是已經上色的 PNG）
- per-frame pose、相對 pose
- 重建／重投影出來的影像（PSNR 的計算輸入）
- 用到的 mask、σ(g)
- 每張圖背後的原始數值（讓圖能被重畫，而不是被重跑）

**達成的效果：一旦原始陣列落盤，之後所有「換圖表樣式、換配色、加一張比較圖」都是純 CPU 操作，永遠不必再碰 GPU。** 這是把「計算」和「呈現」解耦，也是整份計畫最大的平行化槓桿。

輸出位置一律走 `eval_utils/paths.py`，落在 `outputs/<tool>/<exp>/`。

## 四條平行 Lane

### 🔴 Lane A — GPU（關鍵路徑，序列執行，不可中斷）

必須照順序，因為共用同一張卡：

1. **PSNR 評估管線接線**（先做，因為 A2 之後每一步都依賴它）
2. **復現過去計畫的 pair-based 測試**（私人資料集）→ 這是**對照基準**，證明沒有退步
3. **sequence 模式**（私人資料集）→ 這是**本期的核心賣點**：不只 pair
4. **公開資料集推論**：我們的方法 + VGGT + MonST3R + EndoSfM3D

> A2 → A3 是期中報告的主軸（「相對上一期的進步」），**優先級高於 A4**。
> 若時間不足，A4 可以只做一個公開資料集，但 A2/A3 必須完整。

### 🟢 Lane B — 資料與環境（不吃 GPU，第一天就能開始）

與 Lane A **完全並行**，不要等：

- 公開資料集取得與前處理（下載耗時，越早開始越好）
- **EndoSfM3D** 環境建置：程式碼、預訓練權重、相依套件
- **MonST3R** 環境建置（`reference/monst3r/` 已有參考實作，可能省不少事）
- 確認三個 baseline 的**輸入格式與輸出格式**，這決定 Lane D 的對齊工作量

> ⚠️ baseline 環境建置是典型 🔧 間接型任務，**建議各設 3h 停損點**。裝不起來就先記錄狀態，用論文回報的數字當引用值（並在表格中標註為 cited，不是自己重跑），不要讓環境問題吃掉核心實驗時間。

### 🔵 Lane C — 論文盤點（零計算，最先做，產出餵給所有其他 Lane）

- 讀 EndoSfM3D / VGGT / MonST3R，盤點它們**放了哪些表、哪些圖**
- 產出「**我們要放什麼**」的清單
- 反推出 **Lane A 的 dump 規格**（見上方輸出契約）
- 確認各家的**評估協定**：PSNR 怎麼算、有沒有做 scale alignment、用哪些序列

> **這條 Lane 必須跑在 Lane A 前面。** 它是整張圖的上游。

### 🟡 Lane D — 指標與視覺化（CPU，落盤後隨時可做）

- PSNR 計算與比較表
- 視覺化重做（依 Lane C 決定的圖表清單）
- **只要 Lane A 的原始陣列已落盤，這條 Lane 可以無限次迭代而不占 GPU**

## 時序與匯流點

```
時間 →

Lane C  [讀論文/定圖表規格]───┐
                              ↓
Lane A         [PSNR接線]──[A2 pair復現]──[A3 sequence]──[A4 公開資料集]
                              ↑                              ↑
Lane B  [公開資料集下載]──────┘                              │
        [baseline 環境建置]──────────────────────────────────┘

Lane D                        └──[PSNR表]──[圖表迭代（純CPU，可反覆）]
```

**匯流點 1**：Lane C 的 dump 規格 → 必須在 Lane A 的第一次推論前完成
**匯流點 2**：Lane B 的公開資料集 + baseline 環境 → 才能開始 A4
**匯流點 3**：Lane A 落盤 → Lane D 開始，之後兩者解耦

## ⚠️ 風險

**1. PSNR 的定義未確認（阻塞 Lane A）**
PSNR 是影像品質指標，但這條線的方法輸出是幾何量（pose / depth / point map）。所以 PSNR 必然是算在**某種重建或重投影出來的影像**上——**確切定義必須先釐清**，否則「復現過去計畫的測試」無從復現。見文末待確認。

**2. 跨方法的 PSNR 可比性（影響 A4 的可信度）**
EndoSfM3D、VGGT、MonST3R 的原生輸出**不相同**，要讓 PSNR 可比，必須定義一個**共同的成像協定**（同樣的 warp 方式、同樣的 scale alignment、同樣的 mask 處理）。
> 這是 A4 最大的技術風險：協定不統一的話，數字再漂亮也站不住，reviewer 會直接質疑。建議在 Lane C 讀論文時就把協定寫死。

**3. 私人資料集無 GT mask**
已知限制，見週計畫的 gate 監督策略一節。
