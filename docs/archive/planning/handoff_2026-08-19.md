## 3. 協定事實（已從原始碼核實，可信）

### EndoSfM3D（arXiv 2510.22359, github.com/MOYF-beta/EndoSfM3D）

- **depth**（`dares/evaluate_depth_scared.py`）：`MIN_DEPTH=1e-2`、`MAX_DEPTH=150`、
  per-frame `np.median(gt)/np.median(pred)`、scaling 後 clip、`np.array(errors).mean(0)`
  （per-frame 指標**無權重平均**，非像素池化）。與 AF 的 `evaluate_depth.py` 逐行同構，只差 MIN_DEPTH（AF 用 1e-3）。
- **pose**（`dares/evaluate_pose_and_intrinsics.py`）：累積相對 pose 成完整軌跡 →
  evo `align(correct_scale=True)` → `APE(translation_part)`，另報 `RPE(rotation_angle_deg)`。
- **baseline 表整塊繼承自 EndoDAC**，非自行重跑（Fang / Monodepth2 / Endo-SfM / AF 四列與 EndoDAC 逐字相同）。

### AF-SfMLearner（`reference/AF-SfMLearner/`，使用者已放進 repo）

- **pose**（`evaluate_pose.py`）：滑動 `track_length=5` 窗口、每窗獨立平移對齊 + 最小二乘 scale、
  誤差**除以 N 而非 sqrt(N)**、尾端窗口**截短不丟棄**（窗口數 = S−2）。
  論文 Table 10 明文「ATE is averaged over all 5-frame snippets」，且「capped at 150 mm」。
- **frame index 是 1-based**（`datasets/scared_dataset.py:49` 用 `frame_index-1` 讀 tiff）。
  AF 的 seq1 清單 1..410 + loader 的 +1 = 我們的 frame 0..410。

### ⚠️ 未解的矛盾

EndoSfM3D 的 Table 6 引用 AF 等人的 **snippet** 數字，但其程式碼算的是**全序列** ATE，
論文完全沒說明自己那列用哪個。→ 與 AF / Endo-FASt3r 的比較紮實，與 EndoSfM3D 那列存疑。

### split 一致性

`data/train/scared/split/` 與 `reference/AF-SfMLearner/splits/endovis/` **逐行相同**
（410 / 833 / 550 / 15350 / 1705），只差結尾換行。

### 修過的三個 bug

1. `--no_depth` 產生的 `valid_frac.txt` 只有 header → `vf[idx]` IndexError
2. chunked 路徑原本只留第一個 chunk 的 depth → 接 depth 評估索引越界
3. 單 ckpt 執行不建子目錄 → 兩次同 split 的 run 互相覆蓋（VGGT-1B 曾蓋掉 best_ate 的 pose 結果，已重跑）

### 已擋掉的陷阱

snippet ATE 只在 stride-1 幀上有意義。在 depth test split（幀距 3–296）或任何 `--n_frames`
降取樣的 run 上會安靜回傳大而無意義的數字（實測 0.15–1.55）。現在檢查連續性，不連續記 `snippet_skipped`。

## 6. 結果與結論（**尚未經使用者確認**）

數字全文見 `docs/scared_results.md`。摘要：

| 設定 | AbsRel | pose Seq.1 / Seq.2 |
|---|---|---|
| 本期微調 · 全序列 | 0.0449 | 0.0832 / 0.0565 |
| 本期微調 · 單張 | 0.0550 | — |
| VGGT-1B · 全序列 | 0.0488 | 0.1258 / 0.1159 |
| VGGT-1B · 單張 | 0.0758 | — |
| EndoSfM3D（對手） | 0.050 | 0.0791 / 0.0529 |
| Endo-FASt3r（pose 最佳） | 0.051 | 0.0702 / 0.0438 |
| ESRT-Row（上期，pair） | 0.048 | — |

1. **公平設定下我們輸**：單張 0.0550 輸給 DARES/EndoDAC (0.052)、Endo-FASt3r (0.051)、
   EndoSfM3D (0.050)、上期 ESRT-Row (0.048)。
2. **0.0449 主要來自 multi-view**：同 ckpt 單張→全序列改善 18%；
   **zero-shot VGGT-1B 用 multi-view 就到 0.0488**，已贏過表上除 ESRT-Row 外全部。
3. **微調有效**：pose Seq.2 改善 51%、單張 depth 改善 27%。
4. **pose 是短板且 multi-view 救不了**——而 pose 正是這條研究線的主張。

**為什麼不報全序列 ATE**：Sim3 拼接讓該指標擺動 −1% ~ +32%，與 seam 數無關、不可預測。
根因是模型只預測出 0.368 mm 位移而 GT 走 17.10 mm，`correct_scale` 把預測空間 1% 抖動放大 47 倍。
